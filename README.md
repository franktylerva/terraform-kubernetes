# Kubernetes provider with OpenTofu and kind

This tutorial uses OpenTofu to create a local Kubernetes cluster with kind and
deploy an NGINX Deployment and NodePort Service to it. The Kubernetes provider
uses the endpoint and credentials exported by the kind cluster resource, so it
does not depend on the active context in your local kubeconfig.

## Prerequisites

- **OpenTofu** — install with Homebrew on macOS:

  ```sh
  brew install opentofu
  ```

  For other operating systems, follow the
  [OpenTofu installation guide](https://opentofu.org/docs/intro/install/).

- **kind** — install with Homebrew on macOS:

  ```sh
  brew install kind
  ```

  See the [kind installation guide](https://kind.sigs.k8s.io/docs/user/quick-start/#installation)
  for other platforms.

- **kubectl** — install using the
  [Kubernetes instructions](https://kubernetes.io/docs/tasks/tools/).
- **A container runtime** supported by kind, such as Docker. On macOS, install
  and start Docker Desktop before creating the cluster.

Verify the tools are available:

```sh
tofu version
kind version
kubectl version --client
docker info
```

## Create a local TLS certificate with mkcert

mkcert creates locally trusted development certificates. Install it with your
package manager:

**macOS (Homebrew):**

```sh
brew install mkcert
```

If you use Firefox, also install its certificate tools:

```sh
brew install nss
```

**Windows (Chocolatey, in an elevated PowerShell or Command Prompt):**

```powershell
choco install mkcert
```

Alternatively, with Scoop:

```powershell
scoop bucket add extras
scoop install mkcert
```

Install mkcert's local development CA into your system trust store:

```sh
mkcert -install
```

From the project directory, create a certificate for localhost:

```sh
mkcert -cert-file tls.pem -key-file tls-key.pem example.com "*.example.com" example.test localhost 127.0.0.1 ::1
```

This creates `localhost.pem` and `localhost-key.pem`. To make the certificate
available to Kubernetes, first create the kind cluster (for example, by
running `tofu apply`). Then create a TLS Secret in the same namespace as the
Gateway that will reference it. For the `nginx-gateway` in the default
namespace, run this from the project directory:

```sh
KUBECONFIG=terraform-learn-config kubectl create secret tls localhost-tls \
  --cert=localhost.pem \
  --key=localhost-key.pem \
  --namespace=default
```

On Windows PowerShell, set the kubeconfig for the command like this:

```powershell
$env:KUBECONFIG = "terraform-learn-config"
kubectl create secret tls localhost-tls --cert=localhost.pem --key=localhost-key.pem --namespace=default
```

The current example's Gateway uses HTTP. Creating the certificate and Secret
does not enable HTTPS; the Gateway must also have an HTTPS listener that
references `localhost-tls`. Do not commit the generated private key or share
mkcert's local CA private key.

## Map `nginx.example.com` to localhost

Add a hosts-file entry so your computer resolves `nginx.example.com` to the
local machine:

```text
127.0.0.1 nginx.example.com
```

On **macOS**, open the hosts file with administrator privileges:

```sh
sudo nano /etc/hosts
```

Add the line above, save, and exit (`Ctrl+O`, `Enter`, then `Ctrl+X` in nano).

On **Windows**, open Notepad as Administrator, then open:

```text
C:\Windows\System32\drivers\etc\hosts
```

If the file is not visible in the Open dialog, change the file type filter to
show all files. Add the same line and save.

This entry only configures name resolution; it does not expose Traefik from
kind to the host. The Gateway must also be reachable on the host, and its
HTTPRoute must specify `nginx.example.com` as a hostname for host-based routing.

## Deploy the example

Make sure Docker is running, then initialize OpenTofu, review the proposed
changes, and apply them. The apply creates both the kind cluster and the
Kubernetes resources. It also installs the pinned Gateway API Standard-channel
CRDs before installing Traefik and creating the workload:

```sh
tofu init
tofu plan
tofu apply
```

Use the kubeconfig generated by the kind provider to inspect the workload and
Gateway API resources:

```sh
KUBECONFIG=terraform-learn-config kubectl get deployments,services,gateway,httproute
KUBECONFIG=terraform-learn-config kubectl get service traefik -n traefik
```

The NGINX Service remains internal to the cluster. The `nginx-gateway` Gateway
and `nginx-route` HTTPRoute attach to Traefik and forward HTTP requests to that
Service.

The Gateway API CRDs provide the API types, but do not include a Gateway
controller to implement them. The Traefik Helm release enables its Gateway API
provider and creates a GatewayClass and Gateway. Its Service uses NodePort,
which avoids relying on a LoadBalancer implementation that kind does not
provide. Kubernetes assigns the NodePort automatically; this example does not
map that port to the host.

## Clean up

Remove the Terraform-managed resources, including the cluster:

```sh
tofu destroy
```

## Credentials and state

The cluster credentials are managed by the kind provider and passed directly
to the Kubernetes provider. Keep Terraform state files private, and do not
commit credentials or state to source control.
